## 캘린더 내보내기 (ICS → 구글 캘린더) — 설계 + 백엔드 (senior-dev)

담당: senior-dev (오케스트레이터 위임). M7 Backlog **Tier 2**의 "캘린더 내보내기 (ICS → 구글 캘린더)"
착수. 이번 위임 범위는 **설계 + 백엔드까지**이고, 다운로드 버튼/링크를 화면 어디에 둘지는 ui-dev 후속.

### 먼저 확인한 것 (코드 기준)

설계를 바꾼 조사 결과가 두 가지 있었다.

1. **`start_time`/`end_time`은 컬럼도 pydantic 필드도 M1부터 있지만, 값을 입력하는 UI가 프론트
   어디에도 없다.** `frontend/src` 전체에서 이 두 필드가 등장하는 곳은 `api/items.ts`의 요청 타입과
   `types/models.ts`의 응답 타입 선언뿐이고, `AddItemModal.tsx`/`ItineraryItemCard.tsx` 어디에도 시간
   입력 컨트롤이 없다. → **실제 데이터는 전부 NULL**이며(ADR-0006 직전의 `cost_amount`와 같은 상태),
   오늘 내보내면 100% "시간 없는 일정"이다.
2. **여행지 시간대를 저장하는 곳이 없다.** `Trip`은 `name`/`destination`/`start_date`/`end_date`/
   `currency`뿐이고 `destination`은 자유 텍스트라 시간대로 쓸 수 없다.
3. `Day.date`는 `dt.date`(NOT NULL), `ItineraryItem`에 `position`/`address`/`lat`/`lng`/`notes`/`url`/
   `updated_at`이 이미 있다. → **새 DB 필드가 필요 없는 순수 변환 작업**임을 확인.
4. `requirements.txt`는 9줄이고 전부 "없으면 앱이 안 도는 것"뿐. `pyproject.toml` 없음.
5. `frontend/src/api/client.ts`가 `API_BASE_URL`을 export하고 있고, 운영에서는 빈 문자열 +
   `vercel.json`의 `/api/*` rewrite라 브라우저 입장에서 **same-origin**이다.

### 결정 (상세는 [ADR-0008](../docs/adr/0008-ics-calendar-export.md))

1. **일정(ItineraryItem) 1건 = VEVENT 1개.** 시간이 없으면 종일 이벤트
   (`DTSTART;VALUE=DATE` + `DTEND`는 **다음 날** — RFC 5545에서 DTEND는 비포함 경계라 같은 날짜를
   넣으면 길이 0이 된다). 시간이 있으면 그 시각 그대로, 종료 시각이 없거나 시작보다 이르면 +1시간.
   - "Day 하나를 이벤트 하나로 묶고 DESCRIPTION에 나열"은 **기각** — VEVENT는 LOCATION을 하나만
     가지므로 애써 저장한 주소/좌표(M4~M5의 핵심, 캘린더에서 눌러 길찾기로 넘어가는 실질 가치)가
     통째로 날아간다.
   - "09:00부터 1시간씩 자동 배정"도 **기각** — 사용자가 입력한 적 없는 값을 지어내는 것이고, 나중에
     시간 입력 UI가 생기면 가짜 시각과 진짜 시각이 이미 캘린더에 섞여 되돌릴 수 없다.
2. **SUMMARY 앞에 그날의 순번**(`"1. 성산일출봉"`, Day마다 1부터). 같은 날 종일 이벤트들 사이에는
   캘린더가 보장하는 표시 순서가 없는데, 이 앱에서 `position`은 데이터의 의미 자체다(드래그 정렬/
   Day 간 이동이 전부 그걸 다루려고 존재). ICS에 순서 속성이 없으니 사람이 읽는 텍스트로 옮겼다.
3. **시각은 floating time** — `Z`도 `TZID`도 안 붙인다. 해외 여행 앱인데 시간대를 저장하지 않으므로
   `Asia/Seoul` 하드코딩은 도쿄에서 조용히 1시간 어긋난다. floating은 "읽는 쪽 로컬 시간대에서 적힌
   그대로"라 의미가 가장 가깝고, VTIMEZONE 블록도 불필요하다. (구글 캘린더는 가져오기 시점에 자기
   기본 시간대로 고정해버리지만, 그건 `TZID=Asia/Seoul`을 박아도 같은 결과다.)
4. **UID = `item-{item_id}@travel-planner-dtsjs.vercel.app` 고정.** 같은 일정은 몇 번을 다시 내보내도
   같은 UID라 재가져오기가 "추가"가 아니라 **갱신**이 된다. `LAST-MODIFIED`에 `updated_at`,
   `DTSTAMP`에 생성 시각. **`SEQUENCE`는 생략**(리비전 카운터가 없고, `updated_at` epoch 초는
   RFC 5545 INTEGER 상한을 2038년에 넘겨 조용히 깨진다).
5. **`GET /api/trips/{trip_id}/export.ics`** — 저장 없이 매 요청 생성, 세션 쿠키 보호,
   `text/calendar; charset=utf-8` + `Content-Disposition: attachment`(한글 파일명은 RFC 5987
   `filename*=UTF-8''...`, ASCII 폴백 `filename="trip-{id}.ics"` 병기).
6. **`icalendar` 라이브러리는 도입하지 않는다.** 어려운 건 문법이 아니라 CRLF / TEXT 이스케이프 /
   75옥텟 폴딩 세 가지뿐이고 전부 순수 함수로 검증 가능하다. **폴딩은 넣었다** — 한글은 UTF-8에서
   3옥텟이라 주소/메모가 25자만 넘어도 초과해서, 이 앱에선 예외가 아니라 기본 상태다.
7. 라우터는 `app/routers/export.py`로 분리(`settlement.py`/`checklist.py`와 같은 기준).

### 구현

| 파일 | 내용 |
|---|---|
| `backend/app/services/ics_export.py` | **신규.** 순수 모듈. `IcsItem`/`IcsDay` 데이터클래스, `escape_text()`, `fold_line()`, `build_calendar()`, `ics_filename()`. DB/HTTP를 모른다. |
| `backend/app/routers/export.py` | **신규.** `GET /api/trips/{trip_id}/export.ics`. ORM 행 → `IcsDay`/`IcsItem` 변환 + `Response` 헤더 구성. Day가 최대 180개일 수 있어 일정은 N+1이 아니라 `day_id IN (...)` 한 번에 조회. |
| `backend/app/main.py` | `export_router` import + `include_router` 2줄. |
| `docs/adr/0008-ics-calendar-export.md` | **신규 ADR.** |
| `docs/PROJECT.md` | Status 문단, Architecture Decisions, Backlog Tier 2 항목 갱신. |

**DB 스키마 변경 / 마이그레이션 없음.** 기존 컬럼을 읽기만 하는 순수 변환이라
**운영 Neon에 적용할 것이 없고, 백엔드 배포만으로 반영된다**(ADR-0004와 같은 성질).

구현 중 신경 쓴 지점(라이브러리 없이 짤 때 틀리기 쉬운 곳):

- **이스케이프 순서** — 백슬래시를 가장 먼저 치환해야 한다. 나중에 하면 방금 만든 `\,`의
  백슬래시까지 다시 이스케이프해서 `\\,`가 된다.
- **줄바꿈 세 형태** — `\r\n`을 `\n`보다 먼저 처리하지 않으면 CRLF 한 번이 `\n\n` 두 번이 된다.
- **`GEO`(float 쌍)와 `URL`(URI)은 TEXT가 아니라 이스케이프하면 안 된다.** URL은 이스케이프로
  무해화할 수 없으므로 `http(s)` + 공백/제어문자 없음을 만족할 때만 싣는다.
- **폴딩은 문자가 아니라 옥텟 기준**, 그러면서 멀티바이트 문자 중간에서 자르면 안 된다. 이어지는
  줄은 선행 공백 1옥텟도 75에 포함되므로 내용은 74옥텟까지.
- **`quote(filename, safe='')`** — `urllib.parse.quote`의 기본값은 `/`를 남기는데 헤더 파라미터에
  `/`나 `,`가 그대로 들어가면 안 된다.

### 알려진 한계 (의도적, ADR-0008에 기록)

- **앱에서 지운 일정은 이미 가져간 캘린더에서 안 지워진다.** 파일에 "없음"은 "지워라"가 아니다.
  지우려면 `METHOD:CANCEL`이 필요하고 그러려면 내보내기 이력 테이블이 생긴다 → 요구에 없어 기각.
- **해외 여행의 시각 일정은 가져오는 캘린더의 시간대로 굳는다.** 지금은 시각 입력 UI 자체가 없어
  실제 영향 없음.
- **같은 날 종일 이벤트가 여러 개 쌓인다.** 월간 보기에서는 "+N개"로 접힌다(제목 앞 번호로 순서는 읽힘).
- **빈 달력은 RFC 5545 §3.6(최소 1개 컴포넌트)에서 살짝 벗어난다.** 에러를 내거나 더미 이벤트를
  지어내는 것보다 낫다고 판단해 의도적으로 택했다.
- **세션 만료 상태로 링크를 누르면 `{"detail":"Not authenticated"}` JSON이 보인다.** 세션이 90일이고
  그 상태면 페이지 자체가 이미 안 도는 상황이라, 이 엣지 때문에 blob 다운로드 비용을 지불하지 않았다.

### ui-dev 후속 스펙 (다운로드 버튼/링크 배치)

**API 계약**

```
GET {API_BASE_URL}/api/trips/{tripId}/export.ics
  200 → text/calendar; charset=utf-8
        Content-Disposition: attachment; filename="trip-3.ics"; filename*=UTF-8''%EC%A0%9C%EC%A3%BC.ics
  401 → {"detail": "Not authenticated"}
  404 → {"detail": "Trip not found"}
```

**다운로드 트리거 방식: 평범한 `<a href>` 링크. `fetch`+blob 쓰지 말 것.**

```tsx
import { API_BASE_URL } from '../api/client'

<a
  href={`${API_BASE_URL}/api/trips/${trip.id}/export.ics`}
  className="..."
>
  캘린더로 내보내기
</a>
```

- **`download` 속성은 붙이지 말 것** — 서버가 `Content-Disposition`으로 한글 파일명
  (`제주 여행.ics`)을 주는데, `download` 속성이 있으면 브라우저가 그쪽을 우선해 파일명이 바뀌거나
  URL에서 유추한 이름(`export.ics`)이 될 수 있다.
- 쿠키는 그냥 실린다. **운영**은 `VITE_API_BASE_URL`이 빈 문자열 + `vercel.json`의 `/api/*` rewrite라
  same-origin GET이고, **로컬**(5173→8000)은 크로스 오리진이지만 링크 클릭이 최상위 내비게이션 GET이라
  `SameSite=Lax` 쿠키가 실린다. `credentials: 'include'`를 신경 쓸 필요 없다.
- blob 방식을 피하는 이유: 파일 전체를 메모리에 올리고 `createObjectURL`/`revokeObjectURL` 수명을
  관리해야 하며, **모바일에서 blob 다운로드가 OS 캘린더 앱으로 안 넘어가는 경우가 있다**(이 앱은
  모바일 비중이 크다).
- API 클라이언트(`api/*.ts`)에 함수를 새로 만들 필요 없다. 링크 한 줄이면 끝이다.

**배치 판단은 ui-dev 몫**이지만 참고: 여행 카드(`TripListPage.tsx`)는 이미 준비물/정산 펼치기 섹션이
붙어 있어 밀도가 높고, 여행 상세(`DayEditorPage.tsx`)는 "그 여행 안에서 하는 일"이 모이는 곳이다.
어느 쪽이든 `trip.id`만 있으면 된다.

**가능하면 안내 한 줄**: "받은 파일을 구글 캘린더 → 설정 → 가져오기에서 열면 됩니다. 시간을 입력하지
않은 일정은 종일 일정으로 들어갑니다."

## 캘린더 내보내기(ICS) — QA 검증 (qa-reviewer)

담당: qa-reviewer (오케스트레이터 위임). senior-dev의 "103개 체크 통과" 보고를 신뢰하지 않고,

SQLite로 `DATABASE_URL` 오버라이드).

### 검증 방법

1. **백엔드 자동화(38체크, 전부 PASS)** — `venv312\Scripts\python.exe`로 `backend/`에서 실행,
   `DATABASE_URL`을 임시 SQLite로 오버라이드. 스크립트는 스크래치패드에만 둠(커밋 대상 아님).
   - 인증/격리: 미인증 401, 없는 트립 404, 트립 간 일정 미혼입(격리) 확인.
   - 이스케이프: 제목에 백슬래시+쉼표+세미콜론+큰따옴표+줄바꿈이 섞인 문자열
     (`제주도` + 백슬래시 + `, 애월읍; "카페"` + 줄바꿈 + `둘째날`)을 넣고 SUMMARY 라인을
     RFC 5545 이스케이프 규칙으로 직접 재계산한 기대값과 바이트 단위로 비교 — 정확히 일치.
     실제로는 백슬래시 먼저 이스케이프 후 쉼표 이스케이프가 겹쳐 붙어 "백슬래시 3개 + 쉼표"
     형태로 나오는데(원본이 백슬래시 1개+쉼표였으므로), 좌→우로 파싱하면 "백슬래시 이스케이프
     후 쉼표 이스케이프"로 정확히 원복된다 — 이중 이스케이프 버그 없음.
   - CRLF: 응답 전체가 CRLF로만 구분되고 순수 LF가 섞여있지 않음을 확인.
   - 75옥텟 폴딩: 긴 한글 주소/메모(원본을 2배/6배로 늘림)를 넣어 강제로 폴딩을 유발한 뒤,
     (a) 모든 물리 줄이 75옥텟 이하, (b) 응답 바이트 전체가 `bytes.decode("utf-8")`로 예외 없이
     디코딩됨(멀티바이트 문자 중간 절단 시 즉시 `UnicodeDecodeError`가 나므로 이게 가장 강력한
     증거), (c) 접힌 줄을 다시 이어붙인 값이 `escape_text(원본)`과 정확히 일치(왕복 무손실)임을
     모두 확인.
   - UID 안정성: 같은 트립을 두 번 내보내 UID 동일, 일정 제목을 직접 DB에서 수정(PATCH 대신
     ORM으로 재현) 후 다시 내보내도 UID는 그대로고 SUMMARY만 바뀜을 확인.
   - 빈 여행(Day 0개): 200 + `BEGIN/END:VCALENDAR`는 있고 `VEVENT` 0개.
   - Day는 있지만 일정 0개: 200 + `VEVENT` 0개.
   - 시간 있는/없는 일정 혼합: 시간 없는 일정은 `DTSTART;VALUE=DATE`+다음날 `DTEND;VALUE=DATE`,
     시간 있는 일정은 `DTSTART`/`DTEND`에 `Z`나 `TZID` 없이 floating 형식으로 정확히 출력.
   - GEO/URL: 좌표 있는 일정만 `GEO:` 1줄, `javascript:alert(1)` URL은 응답에 전혀 등장하지
     않음(해당 일정 자체는 SUMMARY로 여전히 존재 — URL 필드만 생략됨) 확인.
   - Content-Disposition: 한글 트립 이름으로 헤더를 만들어도 `filename="trip-{id}.ics"`
     ASCII 폴백과 `filename*=UTF-8''%EC...` 퍼센트 인코딩이 둘 다 붙고, 헤더 문자열 전체가
     `str.encode("ascii")`에 예외 없이 성공(= non-ASCII가 헤더에 그대로 새지 않음, HTTP 헤더
     인코딩 에러 없음) 확인.
   - Content-Length가 실제 응답 바이트 길이와 정확히 일치.
2. **실제 서버 기동 + curl (실사용 관점)** — `.env`의 실제 시크릿은 읽지 않고(샌드박스가
   실제로 이를 차단함), `venv312`로 임시 SQLite + 테스트용 시크릿을 환경변수로 오버라이드해
   `uvicorn app.main:app --port 8124`를 별도로 기동. 로그인 → 쿠키로 `export.ics` 요청 →
   응답 헤더/본문을 육안 확인. 각 `VEVENT`가 `UID`/`DTSTAMP`/`DTSTART`를 모두 포함해 RFC 5545
   최소 요건 충족. 테스트 후 서버 프로세스 종료, 임시 DB 파일 삭제. **`dev.db` 수정 시각은
   테스트 전후 동일 — 오염 없음.**
3. **프론트 코드 리뷰 + `git diff`** — `TripListPage.tsx` diff 8줄만 확인:
   - `<a href>` 링크로 `export.ics` URL(API_BASE_URL 조합)을 그대로 사용 —
     `fetch`/blob 없음, `download` 속성 없음.
   - `API_BASE_URL`은 `../api/client`에서 import(하드코딩 URL 없음).
   - `TripEditForm`/`OutOfRangeDaysModal`/`TripChecklist`/`TripSettlement`/`AppSettingsModal`
     관련 파일은 diff에 전혀 등장하지 않음(회귀 없음). 변경 파일은
     `backend/app/main.py`(2줄), `frontend/src/routes/TripListPage.tsx`(8줄),
     `docs/PROJECT.md`, `logs/MASTER_LOG.md`뿐.
   - `npm run build`(`tsc -b && vite build`) 재실행 — 에러/경고 없이 통과.
