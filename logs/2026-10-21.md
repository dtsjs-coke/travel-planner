## 작업: 신규 페이지 "여행 가이드"(`/trips/:tripId/guide`) — 설계 + 백엔드 (senior-dev, orchestrator_pjt 위임)

사용자 요청: 바탕화면의 `portugal_travel_planner_interactive_map.html`(단일 정적 HTML, Leaflet 기반 포르투갈 8박9일
인터랙티브 플래너)의 **구조**를 이 앱에 반영. 원본 파일은 참고용으로 읽기만 함(수정 없음).

사용자가 확정한 범위:
1. 기존 Day 편집 화면은 그대로, 여행별 **읽기 전용 "여행 가이드" 신규 페이지** 추가. 기존 데이터로 구성.
2. 부가기능: 일정 요약표 모달, 필수 명소만 필터, 지도 레이어 전환(일반/위성), 여행 팁/추천 메모 모달.
3. 작은 DB 추가만 허용: 일정 항목의 "필수 방문" 불리언 1칸 + 여행의 "팁/추천 메모" 텍스트 1칸(두 사람 공유, 브라우저 저장 X).
   Day별 제목/설명 컬럼 등은 범위 밖.

원본에 있지만 **이번 범위에서 제외**한 것: 와이너리 랭킹 모달(여행 특화 정적 콘텐츠), 권역 포커스 버튼(리스본/포르투 —
Day 칩으로 대체), OSM 레이어(일반/위성 2종만).

이 세션은 **설계 + 백엔드 + 프론트 타입/API 래퍼**까지. 화면은 ui-dev 후속(명세는 아래 "ui-dev 명세" 섹션).

### 1. 설계 결정 — [ADR-0015](../docs/adr/0015-travel-guide-page-must-visit-and-tips.md)

- `itinerary_item.is_must_visit`: `BOOLEAN NOT NULL DEFAULT false`. 생성 시 선택(기본 false), 수정은 기존
  `PATCH /api/items/{id}`에 필드 추가 — 명시적 `null`은 422(`ChecklistItemUpdate.is_checked`와 같은 방어). 토글 전용 엔드포인트 없음.
- `trip.travel_tips`: nullable 텍스트(`AutoString`), **5000자 상한은 입력 검증으로만**(`MAX_TRIP_TRAVEL_TIPS_LENGTH`).
  `PATCH /api/trips/{id}`에 필드 추가 — 기존 `_normalize_optional_text` 재사용(양끝 trim, 줄바꿈 보존, 빈 값/`null` = 지움).
  `TripCreate`에는 넣지 않음. 응답은 `TripRead` 상속 구조라 목록/상세/생성/PATCH 응답 전부에 실림.
- 편집 진입점: 필수 방문 토글 = Day 편집 화면의 `ItineraryItemDetailModal`. 팁 편집 = 가이드 페이지 팁 모달의
  "편집" 버튼(가이드 페이지 읽기 전용 원칙의 유일한 예외 — 이 값이 보이는 곳이 거기뿐).
- 대안 검토(브라우저 저장 / 별도 테이블 / 범용 태그 / 체크리스트 재사용 / `place_category`에 ★ 인코딩 등)와 감수하는 것
  (팁 last-write-wins, 목록 응답 증가)은 ADR 본문.

### B. 데이터 로딩

```ts
const { data: trip, isLoading } = useQuery({ queryKey: ['trips', tripIdNum], queryFn: () => getTrip(tripIdNum), enabled: Number.isFinite(tripIdNum) })
const days = trip?.days ?? []            // 서버가 sort_order, date 순으로 줌
const { itemsByDayId, isLoading: itemsLoading, errorDayIds } = useTripItems(days)  // 항목은 position 순
```
- queryKey는 `DayEditorPage`와 **완전히 같아야** 캐시를 공유한다(`['trips', id]`, `['days', id, 'items']`).
- 로딩/에러: trip 로딩 중 "불러오는 중...", trip 없음 "여행을 찾을 수 없습니다."(DayEditorPage와 같은 문구).
  항목 로딩 중에는 빈 상태 문구를 띄우지 말 것(`itemsLoading` 게이팅 — 2026-09-08 false empty state 회귀와 같은 함정).
  `errorDayIds`에 든 Day는 리스트에 "이 날짜의 일정을 불러오지 못했어요" 표시.
- Day가 0개면: "아직 날짜가 없어요. 편집 화면에서 날짜와 일정을 먼저 추가해 주세요." + 편집 화면 링크.

### D. Day 색 규칙 (카테고리 색이 아니라 **Day 색**으로 결정)

`place_category`는 구글 `primaryTypeDisplayName`이거나 사용자가 친 자유 텍스트("한식당", "문화센터", "Hotel", 빈 값…)라
현실적인 그룹핑 규칙을 만들면 키워드 사전 유지보수만 생기고 "기타"가 대부분이 된다. 원본 HTML의 "카테고리"도 사실은
권역(리스본/신트라/포르투)이었고, 이 앱에서 그 역할에 가장 가까운 안정적 단위는 **Day**다. 그래서:

- `lib/guideColors.ts`: 팔레트 10색(서로 구분되는 Tailwind 500대 hex) — 예
  `['#2563eb','#16a34a','#ea580c','#9333ea','#0891b2','#ca8a04','#db2777','#4f46e5','#0d9488','#b45309']`,
  `getDayColor(index) = PALETTE[index % PALETTE.length]`. `index`는 `days` 배열에서의 위치(0부터) — `getDayLabel`과 같은 기준.
  **빨강 계열은 팔레트에서 뺀다**(빨강은 "필수 방문" 테두리 전용).
- 마커 색 / 경로선 색 / Day 칩의 색 점 / 요약표의 Day 색 점 / 범례가 전부 이 함수 하나를 쓴다.
- `place_category`는 카드에 **텍스트 배지**로만 보여준다(색 매핑 없음).

### E. 지도 (`GuideMap.tsx`)

**Props**: `days`, `itemsByDayId`(이미 필터 반영된 표시용), `routeItemsByDayId`(필터 미반영 — 경로선용), `selectedDayId`,
`selectedItemId`, `onSelectItem(id|null)`, `mapType`, `onChangeMapType`, `fitNonce`, `onOverview`.

1. `<Map mapId={...} mapTypeId={mapType} mapTypeControl={false} streetViewControl={false} gestureHandling="greedy"
   reuseMaps defaultCenter={첫 좌표 ?? 서울} defaultZoom={...} style={{width:'100%',height:'100%'}}>`
   - `mapTypeId`는 `@vis.gl/react-google-maps` 1.9의 `MapProps`(= `google.maps.MapOptions`)에 있는 **controlled 옵션**이라
     state만 바꾸면 반영된다. 기본 지도 유형 컨트롤은 끄고 우리 토글만 쓴다(중복 UI 방지).
   - `reuseMaps`: 모바일에서 리스트↔지도 탭 전환으로 `<Map>`이 언마운트/재마운트될 때 지도 인스턴스를 재사용(재로딩 비용/깜빡임 감소).
2. **마커**: 좌표 있는 항목만. `<AdvancedMarker position zIndex onClick={() => onSelectItem(item.id)}><GuideMarkerPin .../></AdvancedMarker>`
   - `GuideMarkerPin`(Pin 컴포넌트 대신 HTML): 원형, 배경 = Day 색, 흰 글자, 흰 2px 테두리 + 그림자.
     - 숫자: Day 선택 모드 = 그 Day 안 방문 순서(필터 전 기준 순번 — 필터를 켜도 "3번째 장소"는 3으로 유지),
       전체 경로 모드 = **Day 번호**(1..N).
     - 일반 28px. **필수 방문 = 36px + 빨간(#dc2626) 3px 테두리 + 우상단 작은 "★" 배지**(원본 HTML과 같은 시각 언어).
     - 선택된 항목 = 살짝 확대(scale 1.15) + 가장 위.
   - `zIndex`: 선택 1000 > 필수 100 > 일반 10(겹칠 때 필수가 위).
3. **경로선**: `Polyline`은 이 라이브러리 1.9에서 정식 export(`MapView.tsx`가 이미 사용 중).
   - Day마다 하나: `<Polyline path={좌표 있는 항목들 position 순} strokeColor={Day 색} strokeOpacity strokeWeight />`, 2점 이상일 때만.
   - Day 선택 모드: 선택 Day만, opacity 0.85 / weight 4. 전체 경로 모드: 모든 Day, opacity 0.55 / weight 3. **Day와 Day 사이는 잇지 않는다.**
   - 경로선은 **필터와 무관하게 실제 동선 전체**(`routeItemsByDayId`)로 그린다 — 필수 명소만 이으면 실제 이동 경로가 왜곡된다.
     필터가 켜져 있을 땐 opacity를 0.3으로 낮춰 "배경 동선"으로 보이게 한다.
   - 좌표 없는 항목은 건너뛰고 앞뒤 좌표 항목을 잇는다(별도 표시 없음).
4. **맞춤(fitBounds)**: 내부 `FitBounds` 컴포넌트가 `useMap()`으로 처리. 대상 = 현재 보이는 마커들의 좌표.
   - 트리거: `selectedDayId` 변경, `mustOnly` 변경, `fitNonce` 변경, 최초 데이터 도착. **항목 데이터가 refetch될 때마다 다시 맞추지는 않는다**
     (사용자가 지도를 움직이고 있는데 창 포커스 refetch로 튀는 것 방지 — 의존성을 "Day id/필터/nonce/좌표 개수"로 제한).
   - 0점: 아무것도 안 함(defaultCenter 유지). 1점: `setCenter` + `setZoom(15)`. 2점↑: `fitBounds(bounds, 48)`.
   - 단, `selectedItemId`가 있는 상태로 (모바일) 지도가 마운트되면 맞춤 대신 그 항목으로 `panTo` + zoom ≥ 15.
5. **InfoWindow**: 하나만. `selectedItemId`의 항목에 좌표가 있으면 `<InfoWindow position={...} pixelOffset={[0, -(마커크기)]} onCloseClick={() => onSelectItem(null)} headerContent={제목}>`.
   본문: `★ 필수 방문`(해당 시) / 시간 `HH:MM`(`start_time.slice(0,5)`, end_time 있으면 `~HH:MM`) / `place_category · region_name` /
   `notes` 앞 120자(줄바꿈 보존, 넘치면 …) / `getGoogleMapsLink(item)`이 있으면 "📍 구글지도에서 보기" 새 탭 링크.
   (InfoWindow는 `position` 방식으로 — 마커 ref를 항목마다 관리할 필요가 없다.)
6. **지도 위 컨트롤**(지도 컨테이너 `relative` 안에 absolute):
   - 우상단: 레이어 세그먼트 버튼 `일반 | 위성`.
   - 우상단 아래: "전체 조망" 아이콘 버튼(⤢, `title="전체 조망"`) → `onOverview()` = `fitNonce+1`(현재 보기 모드의 마커 전체로 다시 맞춤, InfoWindow 닫음).
   - 좌하단: **범례**(접이식, 모바일 기본 접힘) — 표시 중인 Day들의 `색 점 + getDayLabel`(전체 모드는 최대 10개 + "…"), 그 아래
     "큰 원 + 빨간 테두리 + ★ = 필수 방문", "숫자 = 방문 순서(전체 경로에선 Day 번호)".
   - 버튼 최소 터치 영역 44px(`min-h-11`, 기존 버튼과 같은 관례).
7. 좌표 있는 항목이 하나도 없으면 지도 위 중앙에 반투명 안내 "지도에 표시할 위치 정보가 없어요"(지도는 그대로 렌더).

### F. 사이드바 / 리스트 (`GuideSidebar.tsx`, `GuidePlaceCard.tsx`)

위에서 아래로:
1. **Day 칩 가로 스크롤**(`overflow-x-auto`, 줄바꿈 없음): 첫 칩 "🗺️ 전체 경로", 이어서 Day별 칩(`색 점 + getDayLabel(day, index)`).
   선택 칩은 진한 배경. 선택 변경 시 선택 칩이 보이게 `scrollIntoView({inline:'nearest', block:'nearest'})`.
2. **"★ 필수 명소만" 토글 버튼**(빨간 계열 pill, 켜지면 채워진 스타일). 옆에 작은 글씨로 "필수 N곳"(현재 범위 기준 개수).
3. **Day 메타 카드**(Day 선택 모드에만; 전체 경로 모드에서는 "여행 개요" 카드로 대체):
   - 배지: `getDayLabel` 결과. **`day.label`이 사용자가 입력한 값이면 그 값이 곧 원본의 "Day 제목"** 역할을 한다.
     `day.label`이 비어 있으면 `getDayLabel`이 자동 라벨(`Day3 11/3(화)`)을 주므로 같은 함수 하나로 끝난다.
   - 날짜: `YYYY.MM.DD (요일)` — `day.date`를 연/월/일 분해해 로컬 Date로(`dayLabel.ts`의 타임존 주의 주석과 같은 방식).
   - 지역: 그날 항목들의 `region_name` 중복 제거 등장 순 최대 3개 `" · "` 연결(넘치면 `외 N`), 없으면 생략.
   - 요약 한 줄: `장소 N곳 · 필수 M곳 · 09:30 ~ 18:00`(시간은 `start_time` 있는 항목의 최소~최대, 없으면 생략).
   - **원본의 "설명" 문단은 없다**(Day 설명 컬럼은 이번 범위 밖 — 만들지 말 것).
   - 전체 경로 모드 "여행 개요" 카드: `trip.destination`, 기간, `Day N개 · 장소 N곳 · 필수 M곳`.
4. **장소 카드 리스트**:
   - Day 선택 모드: 그 Day의 항목(필터 반영). 전체 경로 모드: Day별 소제목(`색 점 + getDayLabel`)으로 묶어 전부 나열.
   - 카드 내용: 왼쪽 순번 원(Day 색, 필수면 빨간 테두리+★ — 마커와 같은 모양), 제목, `★ 필수`(빨간 작은 배지),
     시간, `place_category` 배지 + `region_name`, `notes` 2줄 말줄임(`line-clamp-2`), 우측 📍 구글지도 링크(클릭 전파 차단 — `ItineraryItemCard`와 같은 방식).
   - **좌표 없는 항목**: 리스트에는 그대로 나오되 순번 원 대신 회색 원 + "위치 정보 없음" 작은 회색 배지. 클릭해도 지도 이동 없음
     (카드 클릭 시 카드 아래에 "이 일정에는 좌표가 없어 지도에 표시되지 않아요. 편집 화면에서 장소로 다시 등록하면 표시돼요." 1회 안내, 또는 `cursor-default`로 클릭 불가 처리 — 둘 중 단순한 쪽).
   - 카드 클릭(좌표 있음): `onSelectItem(item.id)` → 지도 `panTo` + zoom ≥ 15 + InfoWindow. 선택된 카드는 링 하이라이트.
     **모바일이면 `mobileTab='map'`으로 자동 전환**(원본과 동일). 전체 경로 모드에서 카드를 눌러도 Day 모드로 바꾸지 않는다(그 위치로만 이동).
   - 마커 클릭 → 데스크톱은 해당 카드로 `scrollIntoView({block:'nearest', behavior:'smooth'})` + 하이라이트.
   - 빈 상태: 필터 켬 + 0곳 → "필수 방문으로 표시한 장소가 없어요. 편집 화면에서 장소를 눌러 ★ 필수 방문을 켤 수 있어요."
     필터 끔 + 0곳 → "이 날은 아직 일정이 없어요."
   - **읽기 전용**: 드래그, 삭제, 인라인 수정, 상세 모달 열기 없음.

### G. 헤더 / 진입점 / 레이아웃

  (lg에서 440px). 사이드바는 `overflow-y-auto`(칩/토글/메타 카드는 sticky 상단, 리스트만 스크롤), 지도는 남은 영역을 꽉 채움.
- **모바일**: 헤더 아래 sticky 세그먼트 토글 `📋 일정 리스트 | 🗺️ 지도 보기`.

  - 지도 탭: Day 칩 + 필터를 지도 위 상단에 얹고(가로 스크롤 그대로), 지도 높이 `calc(100dvh - 헤더 - 토글)`. 범례는 접힘 기본.

1. **필수 방문 토글 — `components/ItineraryItemDetailModal.tsx`**: 제목/구글지도 링크 아래, 입력 필드들 위에 체크박스 스위치

3. **팁 메모 편집 — `TravelTipsModal.tsx`(가이드 페이지)**:

   - `편집` 클릭 → **먼저 `queryClient.fetchQuery({ queryKey: ['trips', id], queryFn, staleTime: 0 })`로 최신 값을 받아** 초안을 채운다
     (상대가 방금 고친 내용을 덮어쓰는 last-write-wins 창을 줄이는 완화책 — ADR-0015 "감수하는 것").
   - 편집 모드: `<textarea maxLength={5000} rows≈14>` + `N / 5000` 카운터 + 플레이스홀더(예: "■ 이동 팁\n- 칼사다 돌길은 비 오면 미끄러워요 …") + `취소`/`저장`.
   - 저장: `updateTrip(tripId, { travel_tips: draft })`(빈 문자열 그대로 보내도 서버가 null로 저장). 성공 시
     `queryClient.setQueryData(['trips', tripId], result)`(응답 `TripUpdateResult`는 `TripDetail` 상위집합) + `invalidateQueries({ queryKey: ['trips'], exact: true })`(목록),
     보기 모드로 복귀. 실패 시 `extractErrorMessage(err, '저장하지 못했습니다.')`를 모달 안에 표시, 초안 유지.
   - 편집 중 닫기(✕/배경/Esc)를 누르면 초안이 바뀌었을 때만 `confirm('저장하지 않은 내용이 있어요. 닫을까요?')`.
   - `lib/errorMessages.ts`의 `DYNAMIC_MESSAGE_RULES`에 `/^travel_tips must be at most (\d+) characters$/` → "팁·메모는 최대 {N}자까지 입력할 수 있습니다." 추가
     (기존 `name|title|text` 규칙 옆). `is_must_visit must not be null`은 정상 UI에서 나올 수 없어 매핑 불필요.
