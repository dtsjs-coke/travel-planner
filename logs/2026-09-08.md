**1) Day 탭 자동 라벨링**
- `frontend/src/routes/DayEditorPage.tsx`에 `formatAutoDayLabel(day, index)` 함수 추가 — `trip.days` 배열의 index(오름차순 정렬됨)로 순번을 매기고, `day.date`('YYYY-MM-DD')를 연/월/일로 직접 분해해 로컬 `Date`를 만든 뒤 `Day{순번} - {MM}/{DD}({요일})` 형식으로 반환. 요일은 `['일','월','화','수','목','금','토']` 테이블에서 `getDay()` 인덱싱.

## M7 QA 재검증 지적 수정: `PATCH /api/items/{id}` `{"title": null}` 명시적 전송 시 500 에러

담당: junior-dev (오케스트레이터 위임). qa-reviewer가 위 title 검증 수정을 재검증하던 중 새로 발견한 버그 — `ItineraryItemUpdate._validate_title`의 `if value is None: return value` 조기 리턴이, "필드를 아예 안 보낸 경우"(pydantic이 validator 자체를 호출 안 함, `exclude_unset=True`로도 걸러짐)와 "명시적으로 `{"title": null}`을 보낸 경우"(validator가 실제 호출됨)를 구분하지 못하고 후자도 통과시켜버림 → 라우터가 `setattr(item, "title", None)` 실행 → DB `title` 컬럼이 `NOT NULL`이라 커밋 시점에 처리 안 된 `sqlite3.IntegrityError`로 500.

### 진행한 작업
- `backend/app/schemas.py`의 `ItineraryItemUpdate._validate_title`에서 `if value is None: return value` 조기 리턴 제거. validator가 호출됐다는 것 자체가 "title 값이 요청에 명시적으로 존재한다"는 뜻이므로(필드 생략은 애초에 호출 안 됨), `None`이든 trim 후 빈 문자열이든 둘 다 `ValueError("title must not be empty")`로 거부하도록 통일. 반환 타입 힌트도 `str | None` → `str`로 정정.

### 검증 (venv312, FastAPI `TestClient`로 파이썬 스크립트 작성해 실행 — 인증은 `/api/auth/login`에 `settings.shared_passcode`로 로그인해 세션 쿠키 확보)
- 테스트용 임시 트립(`__qa_title_validator_test__`) 생성 → Day 생성 → 일정(`title: "원래 제목"`) 생성 후, 그 item에 대해:
  - `PATCH /api/items/{id}` `{"title": null}` → **422** (이전엔 500 → 수정 확인)
  - `PATCH /api/items/{id}` `{"title": ""}` → 422 (기존 동작 유지, 회귀 없음)
  - `PATCH /api/items/{id}` `{"title": "   "}` → 422 (기존 동작 유지, 회귀 없음)
  - `PATCH /api/items/{id}` `{"notes": "메모"}` (title 필드 자체를 안 보냄) → **200**, `title`은 "원래 제목" 그대로 유지 확인 (회귀 없음 — 핵심 케이스)
  - `PATCH /api/items/{id}` `{"title": "정상 제목"}` → 200, 정상 반영
- 테스트로 만든 일정/트립은 `DELETE /api/items/{id}`, `DELETE /api/trips/{id}`로 정리. `dev.db`를 직접 sqlite3로 조회해 트립 1("오사카 여행")·2("안동 여행")가 그대로 남아있고 테스트용 트립은 남지 않았음(트립 2건만 존재) 확인.

## 모바일 연속 스크롤 일정 뷰(트리플 스타일) — 설계 확정

담당: senior-dev (오케스트레이터 위임). **이번 세션은 설계/문서만 — 코드는 한 줄도 변경하지 않음.** 구현은 ui-dev에게 넘긴다.

### 요구사항 (사용자 요청, 참고 앱: 트리플)
- 웹(데스크톱)은 **현행 유지**(Day 탭 클릭 → 그 Day만 리스트+지도 2단).
- 모바일은 지도를 화면 상단에 고정하고, 그 아래로 Day1~DayN 일정을 **탭 클릭 없이 이어붙여 세로 스크롤**. 스크롤해서 보이는 Day 구간이 바뀌면 **상단 고정 지도의 핀이 그 Day 것으로 자동 전환**.
- 부수 요청: Day 라벨 포맷을 `Day1 - 09/10(목)` → `Day1 9/10(목)`으로 변경.

### 내린 결정 (근거는 `docs/PROJECT.md`의 Architecture Decisions에 기록)
1. **데이터 로딩 = Day별 병렬 조회(`useQueries`), 백엔드 변경 없음.** 트립 단위 집계 엔드포인트(`GET /api/trips/{id}/items`) 신설안은 기각 — 기존 캐시 키 `['days', dayId, 'items']`를 유지하면 `AddItemModal`의 invalidate와 `reorderMutation`의 낙관적 업데이트(회귀 위험이 가장 큰 코드)를 그대로 보존할 수 있고, 실사용 Day 수(3~14, 상한 90)에서는 왕복 1회의 이득이 캐시 구조 이전 비용보다 작다. 단, 나중에 뒤집을 수 있도록 **`useTripItems` 훅으로 감싸서** 화면 코드가 로딩 방식을 모르게 한다.
2. **데스크톱/모바일 분기 = JS 미디어쿼리로 택일 렌더**(`hidden md:block` 같은 CSS 분기 금지). 이유: 양쪽 트리를 동시에 렌더하면 `MapView`(Google Maps) 인스턴스가 2개 마운트돼 Map load가 이중 과금된다.
3. **활성 Day 추적 = IntersectionObserver 스크롤 스파이**, 판정선은 상단 고정 블록의 실제 높이를 `ResizeObserver`로 측정해 `rootMargin`으로 환산. 가상 스크롤링 미도입.

#### B. Day 라벨 포맷 (`lib/dayLabel.ts`)
- 최종 포맷: **`Day{순번} {M}/{D}({요일})`** → 예: `Day1 9/10(목)`, `Day12 10/1(수)`
- 대시 없음, 순번과 날짜 사이는 **공백 1칸**, **월/일 모두 0 패딩 없음**(`09/10` ❌ → `9/10` ✅), 요일은 괄호 유지.
- 순번은 `trip.days` 배열의 `index + 1`. 요일 테이블 `['일','월','화','수','목','금','토']`.
- `day.date`('YYYY-MM-DD')는 **기존 코드처럼 연/월/일을 분해해 `new Date(y, m-1, d)`로** 만들 것(`new Date('YYYY-MM-DD')`는 UTC 파싱이라 타임존에 따라 하루 밀림). 이 방어 로직은 기존 `formatAutoDayLabel`에서 그대로 가져오면 된다.
- 공개 API는 `getDayLabel(day, index)` 하나만 export: `day.label?.trim()`이 있으면 그걸 그대로, 없으면 자동 포맷. 호출부에서 `day.label || ...` 하지 말 것(중복 방지).
- `DayEditorPage.tsx`의 기존 `formatAutoDayLabel`은 이 파일로 옮기고 원본은 삭제.

#### C. `hooks/useTripItems.ts`
```ts
export function useTripItems(days: Day[]): {
  itemsByDayId: Record<number, ItineraryItem[]>  // 모든 Day에 대해 키 존재, 없으면 []
  isLoading: boolean                              // 하나라도 첫 로딩 중
  isError: boolean
}
```
- 내부: `useQueries({ queries: days.map(day => ({ queryKey: ['days', day.id, 'items'], queryFn: () => listItems(day.id), staleTime: 60_000 })) })`
- **`queryKey`는 기존과 완전히 동일해야 한다** — `AddItemModal`이 `['days', dayId, 'items']`를 invalidate하는 코드를 건드리지 않고 재사용하기 위함.
- `staleTime: 60_000`은 이 훅에만 준다(전역 `QueryClient` 기본값은 손대지 말 것). 모바일에서 앱 전환 후 복귀할 때마다 Day 수만큼 재요청되는 걸 막는 용도이며, mutation 후 `invalidateQueries`는 staleTime과 무관하게 즉시 refetch되므로 갱신 지연은 없다.
- `itemsByDayId`는 매 렌더 새 객체로 만들어도 무방(하위에 memo된 컴포넌트 없음). 각 배열은 React Query가 참조 안정성을 보장하므로 `MapView`의 `FitToPoints`가 불필요하게 재실행되지 않는다.
- `days`가 빈 배열이면 `isLoading === false`.

#### E. `hooks/useActiveDayOnScroll.ts` (핵심)
```ts
export function useActiveDayOnScroll(dayIds: number[], topOffsetPx: number): {
  activeDayId: number | null
  registerSection: (el: HTMLElement | null) => void   // 각 Day 섹션의 ref로 넘김
}
```
- 각 Day 섹션 DOM에 **`data-day-id={day.id}` 속성을 반드시 붙인다**(콜백에서 `Number(entry.target.getAttribute('data-day-id'))`로 역참조 — 엘리먼트→id 역방향 맵 관리보다 단순하고 버그가 적음).
- Observer 옵션:
  - `root: null` (뷰포트)
  - `threshold: 0`
  - `rootMargin: \`-${topOffsetPx}px 0px -30% 0px\``
    → 판정 밴드 = 뷰포트 상단에서 `topOffsetPx` 아래 지점부터 뷰포트 높이의 70% 지점까지. 상단 고정 블록 바로 밑에서 시작하므로 "지도 아래 보이는 Day"와 일치한다.
- 콜백 로직 (**동시에 여러 섹션이 걸릴 때의 판정 기준**):
  1. `useRef<Map<number, { isIntersecting: boolean; top: number }>>`에 콜백으로 들어온 entry들을 갱신(전체 목록이 아니라 변경분만 오므로 **누적 맵을 유지해야 함**).
  2. `isIntersecting === true`인 항목 중 **`boundingClientRect.top`이 가장 작은(=가장 위에서 시작한)** Day를 활성으로 선택. 이는 "밴드의 상단 픽셀을 점유한 섹션" = 지도 바로 아래에 붙어있는 Day와 같다. `intersectionRatio` 비교는 쓰지 말 것(섹션 높이가 제각각이라 짧은 Day가 부당하게 이긴다).
  3. 교차하는 게 하나도 없으면 **이전 활성 Day를 그대로 유지**(리셋 금지).
  4. 값이 실제로 바뀔 때만 `setState`.
- Observer 재생성 `useEffect` deps: `[dayIds.join(','), topOffsetPx]`. React는 커밋 단계에서 ref를 붙인 뒤 effect를 실행하므로, effect 안에서 등록된 엘리먼트 전부를 `observe()`하면 된다. cleanup에서 `observer.disconnect()`(StrictMode 이중 실행 대응).
- 반환값은 `activeDayId ?? dayIds[0] ?? null` 형태로 폴백(기존 `DayEditorPage`의 `selectedDayId ?? trip?.days[0]?.id ?? null` 패턴과 동일).

#### I. `components/DayEditorMobile.tsx`
구조:
```
<div>
  <div ref={stickyRef} className="sticky top-0 z-10 -mx-6 bg-white px-6 py-2">
    <MapView items={itemsByDayId[activeDayId] ?? []} height="260px" />
    <div className="mt-2 flex gap-2 overflow-x-auto">   {/* Day 점프 칩 — 한 줄 고정, 줄바꿈 금지 */}
      {days.map((day, i) => <button key={day.id} className="shrink-0 whitespace-nowrap ..." onClick={jump(day.id)}>{getDayLabel(day, i)}</button>)}
    </div>
  </div>

  {itemsLoading ? <p>불러오는 중...</p> : days.map((day, i) => (
    <section key={day.id} data-day-id={day.id} ref={registerSection}
             style={{ scrollMarginTop: stickyHeight + 8 }}
             className="pt-4 pb-2 last:pb-[300px]">
      <div className="mb-2 flex items-center justify-between">
        <h2>{getDayLabel(day, i)}</h2>
        <button onClick={() => onAddItem(day.id)}>+ 일정 추가</button>
      </div>
      <ItineraryList items={itemsByDayId[day.id] ?? []} ... />
    </section>
  ))}
</div>
```
세부 규칙:
- **`stickyHeight` 측정**: `useRef<HTMLDivElement>` + `ResizeObserver`로 `getBoundingClientRect().height`를 state에 저장(초기값 320 정도로 두고 마운트 직후 실제값으로 교체). 이 값 하나로 ① `useActiveDayOnScroll(dayIds, stickyHeight + 16)`, ② 각 섹션의 `scrollMarginTop`을 모두 파생시킨다 — **매직넘버를 두 군데 이상 쓰지 말 것**(주소창 유무·폰트 차이로 vh 고정값은 깨진다).
- **배경색 필수**: 고정 블록에 `bg-white`가 없으면 아래 카드들이 지도 위로 비쳐 보인다. 페이지 컨테이너가 `p-6`이므로 `-mx-6 px-6`으로 좌우 full-bleed 처리.
- **섹션 사이에 세로 마진(`my-*`)을 두지 말 것** — 섹션들이 틈 없이 맞닿아야 판정 밴드가 빈 공간에 빠지지 않는다. 간격은 `padding`으로만.
- **마지막 섹션 하단 여백 `pb-[300px]` 필수** — 없으면 맨 아래까지 스크롤해도 마지막 Day가 판정 밴드에 도달하지 못해 지도가 마지막 Day로 안 넘어간다(전형적인 scroll-spy 버그). 300px은 작은 뷰포트(640px)에서도 밴드 시작점(고정블록+16 ≈ 340px)보다 위에 마지막 섹션 하단이 오도록 계산한 값.
- **Day 칩 클릭 = 점프**: `document.querySelector(\`[data-day-id="\${id}"]\`)?.scrollIntoView({ behavior: 'smooth', block: 'start' })`. `scrollMarginTop` 덕에 섹션 헤더가 고정 지도 바로 아래에 멈추고, 이어서 IntersectionObserver가 활성 Day를 자동 갱신하므로 별도 상태 조작이 필요 없다. 현재 활성 칩은 데스크톱 탭과 같은 스타일(`bg-slate-800 text-white`)로 강조.
- 각 Day 섹션은 자기 `DndContext`(`ItineraryList`)를 갖는다 → **Day 간 드래그 이동은 이번 범위 밖**(백엔드 reorder API 자체가 Day 단위). 같은 Day 안에서의 정렬만 동작하면 된다.
- 지도 핀은 `MapView`가 이미 `items` 변경 시 `FitToPoints`로 재조정하므로 추가 작업 불필요. 위경도가 없는 Day(직접 입력 일정만 있는 경우)로 넘어가면 지도는 직전 화면을 유지한다 — 의도된 동작.

## 모바일 연속 스크롤 일정 뷰 — qa-reviewer 지적 수정: 로딩 중 false empty state

담당: ui-dev (오케스트레이터 위임). qa-reviewer가 위 구현을 검증하다가 발견한 [보통] 등급 회귀 1건 수정.

### 문제
`useTripItems`(`hooks/useTripItems.ts`)는 아직 데이터가 오지 않은 Day도 `results[index]?.data ?? []`로 즉시 빈 배열을 채워 넣는다. `DayEditorDesktop.tsx`는 `items = activeDayId !== null ? itemsByDayId[activeDayId] ?? [] : []`를 그대로 `<ItineraryList items={items} .../>`에 넘기고 있어, 로딩 중에도 `items.length === 0`이라 "등록된 일정이 없습니다"가 즉시 렌더된다. 그 결과 페이지 로드 직후 `{itemsLoading && <p>불러오는 중...</p>}`과 "등록된 일정이 없습니다"가 잠깐 동시에 보이다가 실제 데이터로 바뀌는 깜빡임이 발생. 리팩터 이전 원본(`git show 373898b:frontend/src/routes/DayEditorPage.tsx`)은 `{items && (<ItineraryList items={items} .../>)}`였고, React Query `data`가 로딩 중 `undefined`라 이 조건이 자동으로 거짓이 되어 방어됐는데, 리팩터 과정에서 이 방어가 사라졌다.

### 진행한 작업
- `frontend/src/components/DayEditorDesktop.tsx` — `<ItineraryList>`를 `{!itemsLoading && (<ItineraryList items={items} .../>)}`로 게이팅. 그리드 컨테이너(`grid gap-4 md:grid-cols-2`)와 `<MapView items={items} .../>`는 원본과 동일하게 로딩 중에도 그대로 렌더(원본이 `items ?? []`로 지도는 항상 그렸던 것과 동일한 동작 — items가 빈 배열이어도 지도는 핀만 없을 뿐 깨지지 않음). "불러오는 중..." 문구(`{itemsLoading && <p>...</p>}`)는 기존 위치 그대로 유지.
- `frontend/src/components/DayEditorMobile.tsx` — 확인 결과 이미 `itemsLoading ? <p>불러오는 중...</p> : days.map(...)` 구조로 `<ItineraryList>`를 포함한 전체 Day 섹션 자체가 `itemsLoading` 플래그로 게이팅되어 있어 동일한 회귀가 없음. **코드 변경 없음.**

### 검증
- `npm run build`(`tsc -b && vite build`) — 타입 에러 없이 통과.
- 코드 추적으로 확인: `itemsLoading === true`인 동안 `!itemsLoading && (...)`가 거짓이 되어 `<ItineraryList>`가 렌더 트리에서 완전히 빠짐(원본의 `{items && (...)}` undefined 방어와 동일한 효과). `itemsLoading === false`가 되면 `items = itemsByDayId[activeDayId] ?? []`(실제 데이터)로 정상 렌더 — 로딩 완료 후 동작은 변경 전과 동일해 회귀 없음.
